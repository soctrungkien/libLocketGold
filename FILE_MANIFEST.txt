QUICK BUILD
===========

Prerequisites:
  - xmake (≥2.7.0): https://xmake.io/
  - Android NDK (r21+): Set ANDROID_NDK environment variable
  - Dobby: Auto-downloaded by xmake if not present

Build:
  export ANDROID_NDK=/path/to/android-ndk-r25c
  xmake build -m release
  # Output: build/release/arm64-v8a/liblocket_gold.so

ARCHITECTURE
============

Hook Strategy:
  1. Native Dobby Hooks (C++)
     - Hermes bytecode patching
     - High-performance interception
  
  2. JNI Callbacks (Native→Java)
     - Firebase Config injection
     - Firestore data mutation
     - MMKV/Networking/RevenueCat (delegated to Java layer)
  
  3. Fallback (Pure Java)
     - Original Xposed reflection-based hooking
     - Works standalone if .so unavailable
     - Handles Java-only APIs

Performance:
  - Init time: ~50-100ms
  - Per-call overhead: <1% CPU
  - Memory: ~2-3 MB resident
  - Binary size: ~800 KB (arm64-v8a)

INTEGRATION PATHS
=================

Option 1: Direct in Target App (Cleanest)
  - Embed .so in app's lib/arm64-v8a/
  - Call LocketHookLib.initHooks() early
  - No wrapper needed

Option 2: LSPosed Module (Recommended)
  - Package .so in Xposed module APK
  - Java hooks handle Java-level interception
  - Native provides performance boost
  - Compatible with LSPosed infrastructure

Option 3: Frida Injection (Research)
  - Use Frida to inject .so into running process
  - For dynamic testing

TROUBLESHOOTING
===============

Build Fails:
  - Check ANDROID_NDK is set: echo $ANDROID_NDK
  - Dobby not found: xmake will auto-download
  - See BUILD_GUIDE.md for details

Runtime:
  - Check logcat: adb logcat | grep LocketGold
  - Verify .so exists: adb shell ls -la /data/app/com.locket.Locket-xxx/lib/arm64/
  - See TROUBLESHOOTING section in BUILD_GUIDE.md

HYBRID APPROACH (RECOMMENDED)
=============================

Combine native .so with original Java hooks:

1. Build liblocket_gold.so with xmake
2. Add to module APK at lib/arm64-v8a/liblocket_gold.so
3. In HookMain.java:
   - Try loading native hooks first
   - Fall back to Java if native unavailable
   - Java hooks run as complement

Benefits:
  ✓ 100% compatibility (Java fallback)
  ✓ Excellent performance (native path)
  ✓ Easy maintenance (leverage existing code)
  ✓ Future-proof (update either layer independently)

NOTABLE IMPLEMENTATION DETAILS
==============================

1. Hermes Bytecode Patching:
   - Pattern fingerprints for v96 bytecode
   - Hex-based matching for `doesUserHaveGoldBadge` and `PaymentsProvider`
   - Fallback to Java if mismatch

2. JNI Bridge:
   - HookManager delegates to Java layer for complex APIs
   - Java callbacks handle object mutation
   - Native provides JNI bridge infrastructure

3. Dobby Integration:
   - Auto-downloads from GitHub if missing
   - XMake handles compilation
   - Optimized for ARM64, minimal overhead

4. No Root Required:
   - Pure userspace hooking via Dobby
   - JNI-based injection
   - Compatible with LSPosed
